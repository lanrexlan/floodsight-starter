## P0 — Corrections (wrong today, credibility- or safety-critical)

### 1. "Real" training data is 76% synthetic, and the deployed model claims otherwise

`data/processed/real_training_dataset.csv` had 2,536 rows: only 616 from
actual SAR/FwDET-labeled events (Lekki 2024, Lekki 2021). The other 1,920
were generated by `scripts/10_augment_training_data.py`, which assigns
depths from a severity-scaled lognormal and reuses Lekki terrain cells for
15 other events. The deployed bundle said `trained_on_synthetic_data: False`,
so `/depth/predict` told users predictions were real.

Compounding problems:

- **Split leakage.** Random row-wise `train_test_split` puts every event in
  both train and test. R²=0.31 (Phase 22) largely measures how well the
  model learned the hand-crafted lognormal — not real predictive skill.
- **MAE=0.314 m is worse than the pitch deck's ±0.3 m claim**, even on the
  leaky split.
- This recreates exactly the deck-vs-repo credibility gap that ROADMAP.md
  Phase 0 was written to close.

**Fix applied:**
- Added a `label_source` column to the dataset (`sar_fwdet` vs
  `synthetic_augmented`); `scripts/10_augment_training_data.py` now writes it.
- `floodsight/ml/train.py` (now the single canonical trainer) splits by
  event group (GroupShuffleSplit) so no event leaks between train and test,
  and reports metrics separately for all held-out rows and for
  **real-labeled held-out rows only** — the only number that should ever be
  quoted externally.
- Model bundle now stores `label_provenance` (real/synthetic row counts and
  fraction); the `/depth/predict` response and `/depth/model_info` expose it.
- Model retrained; see HANDOFF.md for the honest numbers.

### 2. Warning SMS always loses its opt-out instruction (and bills 3×)

The Warning template was 178 chars with a typical area name; the 160-char
trim always cut "Reply STOP to opt out" and left a dangling `|…`. The
appended `…` (U+2026) is not GSM-7, silently switching the whole message to
UCS-2 encoding → 3 billed segments per Warning. NDPR opt-out compliance
issue + 3× SMS cost.

**Fix applied:** `floodsight/notifications/sms.py` rebuilt — the STOP
suffix is composed last and never truncated (the details section shrinks
instead), all characters are GSM-7 safe, and a unit test asserts every
template/area combination stays ≤160 GSM-7 chars with the opt-out intact.

### 3. Unauthenticated endpoints on a life-safety system

- `DELETE /subscribe/{phone}` — anyone could unsubscribe any resident from
  flood warnings by guessing/enumerating numbers.
- `POST /verify` — anyone could poison the verification log that drives
  recalibration; `GET /verify/summary` publicly exposed reporter names and
  notes (PII).
- `GET /depth/predictions_log` — fully public.
- Bearer check used non-constant-time string comparison.

**Fix applied:** shared `api/auth.py` with `hmac.compare_digest`;
`DELETE /subscribe`, `POST /verify`, verification detail listing, and
`/depth/predictions_log` now require `Authorization: Bearer <secret>`
(`VERIFY_SECRET` for field partners, falling back to `DISPATCH_SECRET`).
`GET /verify/summary` returns only aggregate counts without auth.

**Still pending (P2):** `POST /subscribe` upsert lets an attacker move an
existing subscriber's alert location using only their phone number. Proper
fix is OTP confirmation via Africa's Talking — see item 10.

### 4. Verification & prediction logs lived on Render's ephemeral disk

`data/logs/*.jsonl` is wiped on every deploy/restart — and Render
auto-deploys on every push. The entire Phase 6 feedback loop silently lost
its data.

**Fix applied:** logs now write to Supabase (`prediction_log`,
`verifications`, `dispatch_cells` tables — migration in
`scripts/sql/03_logs.sql`), with JSONL fallback for local dev when Supabase
env vars are absent. `scripts/recalibrate.py` reads Supabase first.

## P1 — Corrections (wrong, but lower blast radius)

### 5. Two training pipelines had diverged

`floodsight/ml/train.py` (the documented retrain path) and
`scripts/09_train_flood_depth.py` (which built the deployed model) used
different hyperparameters, different metric key names, and only 09 saved
`hand_impute_median`. Retraining via the documented command would have
silently reverted HAND imputation from the deployed 0.46 m to a hardcoded
3.0 m fallback — a real prediction shift.

**Fix applied:** `floodsight/ml/train.py` is the single canonical trainer
(group split, provenance, `hand_impute_median` always saved, consistent
metric keys). `scripts/09_train_flood_depth.py` now delegates training and
bundle-saving to it and tags its SWMM rows `label_source="swmm_synthetic"`.
`floodsight/ml/predict.py` no longer has a silent 3.0 m default.

### 6. Recalibration analysis measured the wrong thing

`scripts/recalibrate.py --analyse` matched field verifications to
`/depth/predict` calls (i.e. dashboard clicks) by proximity only, ignoring
`event_date`. FP/FN rates must be computed against what the system
*dispatched*.

**Fix applied:** `/alerts/dispatch` now snapshots every Watch/Warning cell
(cell_id, lat/lon, level, event_date) to `dispatch_cells`;
`recalibrate.py --analyse` matches verifications to that snapshot by
event_date + location, falling back to the old prediction-log match only
when no dispatch snapshot exists for the date.

### 7. Stale HANDOFF.md

Still described the 616-row / R²=0.106 / "Phase 6 next" state; the repo was
at Phase 22 with 15 LGAs, a 200 m grid, and different numbers.

**Fix applied:** HANDOFF.md rewritten to the current state, including the
honest post-fix metrics and this document as the work queue.

## P2 — Missed opportunities

8. **Non-rainfall flood drivers.** **Partially done:** tidal/coastal signal
   added (`floodsight/forecast/marine.py`, Open-Meteo Marine sea level,
   72 h horizon) — surfaces as a `coastal` block in `/forecast/alerts` and
   `/forecast/summary` and a HIGH TIDE line in the morning briefing. The
   advisory threshold (1.0 m MSL) is a placeholder — calibrate against
   NiHSA tide gauge records and the 2021-07 surge event. **Still open:**
   dam-release monitoring (Oyan/Ogun) needs NiHSA / Ogun-Osun RBDA data or
   GloFAS discharge on the Ogun reach (GloFAS remains untested from
   Phase 2), and the coastal signal is not yet wired into per-cell alert
   levels — only into operator-facing surfaces.
9. **All-clear messages.** **Done:** `/alerts/dispatch` now sends one
   stand-down SMS to subscribers whose cell is quiet after a Watch/Warning
   today or yesterday (deduplicated via alert_log level 'All Clear' —
   requires `scripts/sql/04_inbound_otp.sql`).
10. **OTP subscription confirmation + STOP webhook.** **Done:**
    `POST /at/incoming` (token-protected) handles STOP/START keywords, and
    `REQUIRE_OTP=true` gates subscriptions behind a 6-digit SMS code
    (`/subscribe` → `/subscribe/confirm`; pending table in
    `scripts/sql/04_inbound_otp.sql`; dashboard prompts for the code).
    OTP defaults OFF until tested in the AT sandbox — the upsert-hijack
    hole stays open until it is switched on.
11. **Morning briefing → subscriber base.** **Done:** the briefing sends to
    all active Supabase subscribers when SUPABASE_URL/KEY are set
    (`AT_RECIPIENTS` is now the fallback). Add both secrets to the GitHub
    Actions repo settings.
12. **Inbound verification channel.** **Done:** the same webhook accepts
    "FLOOD", "FLOOD 0.5", "FLOOD 50CM", and "NOFLOOD"/"DRY" from
    registered subscribers, creating verification records identical to
    `POST /verify` (keyed to their registered location, today's date).
